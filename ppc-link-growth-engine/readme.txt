Compliance-first backlink discovery, qualification, submission packaging, outreach drafting and backlink monitoring for Pure Peptides Canada.

== Description ==

PPC Link Growth Engine discovers websites that could legitimately link to Pure Peptides Canada, scores them on a transparent 100-point model, locates their real submission pages and editorial contacts, prepares personalised listing packages and outreach emails, submits listings only where explicitly authorised, and monitors every acquired backlink.

* Discovery: rotating search queries, curated Canadian seed catalog, competitor backlink mining, unlinked mentions, broken links.
* Qualification: polite crawling, relevance and risk analysis, SE Ranking / Ahrefs / Semrush / Moz metrics, never fabricated.
* Submissions: form detection, field mapping, verified-fact descriptions, explicit authorisation gates, review queue, listing verification.
* Outreach: eight personalised approaches, CASL/CAN-SPAM identification and unsubscribe, approvals, limits, follow-ups, reply tracking. A new campaign gets drafts at once for every matching prospect.
* Autopilot: one confirmed switch lets the engine approve and send outreach and submit listings without asking first, inside the caps, the send window and every hard limit (no sign-ups, no CAPTCHA bypass, no comment posting, robots.txt, claims filter, CASL/CAN-SPAM, suppression, storefront gate, no paid listings).
* Monitoring: scheduled checks, change and loss detection, provider and GA4 imports, notifications and digests.
* Grow now: one click on the Overview runs every stage once, in order, and lists what happened and what needs you.
* Storefront compliance check: pauses automated submissions and outreach sending while the storefront presents products for consumer use.
* On-site SEO: read-only site audit, IndexNow notifications and internal-link suggestions, applied when you click Apply or, under Autopilot, the best ones automatically on pages that show them to visitors (with one-click undo).
* Verified opportunities: 595 researched listing and outreach opportunities bundled with the plugin, imported as owner tasks.
* Link Growth Submitter role: hand the owner tasks to a staff member or assistant who sees only that queue.
* Dashboard: Overview, Prospects, Submissions, Outreach, Backlinks, On-site SEO, Automation, Settings, Logs.

== Installation ==

1. Upload the plugin zip under Plugins → Add New → Upload Plugin and activate.
2. Open Link Growth → Settings, review the business profile and add your API keys.
3. Run Discover and Evaluate from the Automation Center, then enable automation.

== Changelog ==

= 1.2.4 =
* Fixed: the plugin added background work while the server was struggling. Right after a plugin update the live store answered with timeouts (HTTP 504) for about 20 minutes: PHP's code cache (OPcache) was full, an UpdraftPlus backup held PHP workers for minutes, and every few minutes the plugin's scheduler took another worker for up to 20 seconds. Pages took 16 to 27 seconds with the plugin on and 2 to 7 seconds with it off.
* New: background work pauses by itself while PHP's code cache is restarting, while a backup is running (UpdraftPlus is recognised by its scheduled resume event; other backup plugins can report through the ppclg_backup_running filter) and for 10 minutes after the plugin is updated or activated. While paused, the scheduler tick starts no job and spends no limit, "Kick scheduler" starts nothing, and Grow now steps wait instead of failing; the Grow now panel then asks the server about once a minute instead of every few seconds, and Stop still ends the run at once. Everything continues by itself once the pause is over: nothing is lost, only delayed, and outreach keeps its send window and daily limits.
* New: the Overview, the Automation page and the Grow now panel say why, for example "Paused: a backup is running (resumes automatically)." The Logs record the start and the end of each pause once. "Run now" on a stage still runs it when you click it, and its answer says that background work is paused.
* New: the ppclg_pause_background filter lets a site owner or host pause background work (return true or a short message), or let it run despite a detected reason (return false).
* New: Tools → Site Health warns when PHP's code cache is full ("PHP's code cache (OPcache) is full", critical) or almost full (more than 90% used, recommended), with the numbers and the exact change: in the php.ini (or a conf.d file) that PHP-FPM uses set opcache.memory_consumption=256, opcache.interned_strings_buffer=32 and opcache.max_accelerated_files=32531, then restart PHP-FPM; on managed hosting, ask your host. A server that already has at least these sizes is told to about double the one that is running out instead, never to lower a setting. When only the interned strings buffer is full, the warning says so: PHP still caches code then, the rest of the cache only fills up sooner. While it is full, the Overview shows the same notice. A full cache alone never pauses anything, so Autopilot keeps working.

= 1.2.3 =
* Fixed: automatic internal links used the brand name as link text and crossed languages. On the English Terms of Service page, "Pure Peptides Canada" was linked to the French About page (its first Rank Math focus keyword is "pure peptides canada") and "Peptides Canada", the end of the brand name in "belong to Pure Peptides Canada or its licensors", to the home page (focus keyword "peptides canada").
* New rule, brand name: the brand is never link text, in suggestions or automatic links. The brand is the brand name, the legal name, every brand term in Settings → Discovery (Brand terms for mention scans), the WordPress site title and the site domain with and without its ending ("purepeptidescanada.com", "purepeptidescanada"), compared without regard to capitals, spaces, punctuation or accents. A product or page whose anchor is the brand, or part of it ("Peptides Canada", "Pure Peptides"), is not linked by those words. A page whose first focus keyword is the brand is linked by its next focus keyword that is usable instead (the French About page by "fournisseur canadien de peptides"); a first keyword that is unusable for another reason keeps the page out, as before. Words inside the brand name where it is written in a page ("Peptides Canada" in "Pure Peptides Canada") are never linked, also for a target whose own words are not the brand; the next mention outside the name is used instead. A link that holds the whole brand name and more words ("Pure Peptides Canada reviews") is not refused.
* New rule, language: a page only links to pages in its own language. The language of an item is the one Polylang or WPML gives it, else the ppclg_post_language filter, else, for the site's French pages (meta ppc_en_counterpart), the language their address starts with (/fr/), else a two-letter language code at the start of its address (/fr/, /es/; only real ISO 639-1 codes), else the language its text is written in, else the site language. The text is read on English and French sites, for English and French: a page is in the other language only when its title, excerpt and content clearly read as it (at least 8 of its common short words such as "le", "les", "nous", "avec", 4 of them different, and three times as many as of the site language), so the French pages at the site root (/acheter-peptides-canada/, /peptides-recherche-quebec/) are French; a short or mixed text keeps the site language. A French page without a /fr/ address but with ppc_en_counterpart is French by its text as well (before, its language was not known). A French page is never offered an English target and the other way round; an English and a French product with the same title are no longer dropped as ambiguous: each language links to its own.
* Existing suggestions: waiting suggestions (and ones set aside as not shown) that break either rule are closed under "No longer valid" on the next suggestion run and on the next automatic run, with the reason: "Not suggested: the link text is your brand name." or "Not suggested: the target page is in another language." They are never added automatically, and Apply closes them the same way instead of linking. Links already applied are left as they are (a person may have chosen them), and dismissed or undone suggestions stay as they were. A suggestion run that was in progress when the plugin was updated starts again under the new rules.

= 1.2.2 =
* Fixed: Autopilot added internal links where nobody sees them. The one live automatic link went into the content of the home page, whose theme front-page template is hard-coded and never prints that content. Before an automatic link, the engine now checks that the item's public page shows the item's text and the words around the anchor: the posts page and the WooCommerce cart, checkout and account pages are recognised from the settings, every other item (also the shop page, whose content classic themes print as the shop description) gets one anonymous request of its own address (no cookies, no redirects, HTML only, never text/markdown, 8-second timeout, at most 3 pages per run and per PHP request, 2 seconds apart). The answer counts only when it is HTTP 200 HTML that names the item (body class page-id-N / postid-N, woocommerce-shop for the shop page, shortlink or canonical address), and the words must appear as consecutive words in the visible body text (an anchor alone never counts). A post split with page breaks (<!--nextpage-->) is compared by its first page, which is what its address shows; suggestions on later pages are left for you instead of being set aside (also when the first page has too little text to compare), and text on later pages never counts as evidence that the page hides its content.
* New: suggestions on a page that does not show its content (or whose page does not show those words) move to "Not shown on the page" with the reason ("Not added: this page's template doesn't display its content, so visitors and Google wouldn't see the link."); they are neither added automatically nor counted as waiting for review. Automatic links already on such a page are taken back out through the undo path (exactly the earlier content when the page was not edited since, otherwise only the link; a revision first; audit "seo.internal_link_auto_removed" as "system:autopilot"), so the live home-page link is removed on the first run after the update. An automatic link someone already removed in the editor is closed instead ("Closed: this automatic link is no longer in the item …"): it is not counted or audited as removed and, as in 1.2.1, never suggested or added again. A deleted item's suggestions and automatic links are closed as no longer valid without a request and never hold up the check of the other pages, and an unpublished item is not requested. Everything is checked again when the page is edited, its template or the theme changes, or it becomes or stops being the front page, the posts page or a WooCommerce page, and after 7 days; when a page shows its content again its suggestions return to the queue. Applying such a row by hand still works and says that visitors will not see the link.
* New: a page check that cannot be completed (a network error, a timeout, an answer other than 200, a login or challenge page, too little text, or the item's words shown without their bold or italic formatting, as in a plain-text excerpt) decides nothing: the item is skipped for this run and retried after about 6 hours, and its rows say "Not checked yet: …". A timeout, HTTP 429 or 5xx, a challenge or an answer slower than 5 seconds stops further page requests for the rest of the run and pauses page checks for 10 minutes in every run and request (transient ppclg_render_check_pause), so neither the next round nor a Grow now click asks a busy host again right away. When a run stops for time or for the page limit with links left for the day, the internal_links job runs again 15 minutes later without refreshing the suggestions; a Grow now step leaves that round to the scheduler instead of running it at once.
* Fixed: the 8 highest-relevance suggestions were all left for review with "Not applied automatically: WordPress would re-filter other markup in this item when saving it." Background saves run without a user, so kses would strip the inline SVG diagrams and FAQPage JSON-LD that an administrator wrote into those articles. Such a save is now made as the administrator who switched Autopilot on under its 1.2.2 text (policy 1.2.2-1, which now says that Autopilot saves such a change as your account and takes its own automatic links back out of pages that don't display them; a consent given under the earlier text keeps the rest of Autopilot running but not this, so switch Autopilot off and on again once, and the Autopilot card says so) or, while Autopilot is off, as the user who switched "Add the best internal links automatically" on (recorded in ppclg_auto_links_consent only when it is switched on with its confirmation, which Settings now asks for also while Autopilot is on, and deleted when it is switched off, so a consent that was taken back never comes back). It is for that one save, and only while that user still exists, may edit the item and may save unfiltered HTML (never with DISALLOW_UNFILTERED_HTML; on multisite only a super admin). The previous user is restored in a finally block, the revision is credited to that user and the audit entry keeps "system:autopilot" as the actor with saved_as. Only the plugin's own link to a page of this site is added; every other byte stays as the administrator saved it, which the existing byte-identical check confirms. Otherwise the refusal stays. Refusals stored by 1.2.1 are tried again once a user qualifies.
* Fixed: outreach drafts and follow-ups were signed "Pure Peptides Canada" twice when the sender name was the brand. The default signature leaves the sender name out when it equals the brand (ignoring case and spaces), and no signature line, also in a signature typed in Settings, is repeated right below itself.
* Changed: GET /seo/links returns one page of suggestions (per_page 1–500, default 100; page) with total, pages, page and per_page, instead of up to 500 at once (449 KB on the live site). New filters: status=refused (pending suggestions the automation left for a person, with auto_skip giving the reason) and status=not_shown; items carry auto_skip, note and render_note; counts and the "auto" figures include not_shown, refused / left_for_you and removed. The On-site SEO page lists 50 at a time with Previous / Next, shows the new filters and each row's reason, and "Apply all" applies the rows on the page ("Apply these N") when there are several pages.

= 1.2.1 =
* Fixed: drafts built before the outreach postal address was changed were refused on every approval, automatic and manual, with "Not approved: Body must contain the sender postal address.", because their compliance footer still carried the old address; automation never retried them and the campaign card said they needed editing. The footer of a message that is not sent yet (draft, approved, scheduled, failed or rejected) now follows the current settings: before every approval, before every send and on every manual save, the "<brand> · <postal address>" line and the unsubscribe line below it are rebuilt from Settings (outreach.postal_address, or the business address under Settings → Site when that is empty, and site.brand_name) and replaced in place. The rest of the email and its unsubscribe link token stay exactly as they were, a missing footer is added, and sent, replied, closed or opted-out messages are never changed. Each rewrite at approval or send is recorded once in the audit log ("outreach.footer_refreshed"). A manual save records no separate entry: its "outreach.message_updated" entry says footer_refreshed: true.
* Fixed: drafts already stuck with "Not approved: Body must contain the sender postal address." (or "… the unsubscribe link.") count as waiting instead of "need editing". Automation approves them wherever it already approves drafts: under Autopilot (on its next run, when Autopilot is switched on, or at once when you save the address or brand in Settings), and without Autopilot in the "Auto:" campaigns when Settings has Outreach autosend on and Require individual approval off (on the next outreach run, or at once when you save Settings). Otherwise they wait for you, and approving them yourself now works.
* Fixed: saving an edited draft whose footer carried an old address added a second footer under the stale one. The stale footer is now replaced whole, also when its address runs over several lines or a blank line was added above the unsubscribe line, and a stale copy left above a current one by 1.2.0 is removed. A footer edited so that it can no longer be recognised (for example the "·" between brand and address replaced) is not guessed at: the save says so, and approval and sending refuse the draft with a note to delete the old line or type the current address into it, instead of mailing the old address above the new one. Such a draft counts as needing an edit and is not retried on every run.
* Fixed: a postal address over 200 characters, or one with an HTML entity or a space before a colon, was shortened or rewritten in the footer, so the draft could never pass the postal address check, and under Autopilot it was retried on every run while the card said "Sending automatically". The footer now carries the address exactly as configured, on one line (a line break becomes ", ").
* Every compliance rule is unchanged: each email still needs the sender identification, the postal address and a working unsubscribe link, and is refused without them.

A new campaign now gets drafts at once for every eligible prospect whose best opportunity matches its approach (active, conspicuously published contact; not suppressed; outside the contact cool-down; one open message per website; verified-database owner tasks excluded as before). The response reports drafted / eligible / remaining / reasons; the auto outreach stage continues the rest in the background and now also fills campaigns you created, not only the "Auto:" ones. Unsent drafts an "Auto:" campaign holds for the same approach move into your new campaign instead of being skipped as "already exists". When nobody is eligible the card says why in plain words.
* Fixed: creating a campaign from the Messages tab left the message list on screen; the page now switches to Campaigns and shows the new card, and the Messages campaign filter lists the new campaign.
* New: every campaign card shows "What happens next" (waiting for your approval, sending automatically with today's count and the next send window, paused because the sender email cannot receive mail, and so on) and offers "Approve all drafts" (POST /outreach/campaigns/{id}/approve-drafts). The Build drafts picker lists only matching prospects by default (GET /outreach/campaigns/{id}/candidates), with "Show all qualified prospects" to pick others. A draft is refused when the website already has an open message elsewhere, and the reason names that campaign.
* New: Autopilot (Overview and Automation pages; POST /automation/autopilot {enabled, confirm}). On: campaigns and drafts are approved automatically and sent inside the daily/weekly caps and the send window, listings are submitted in "auto" mode wherever every safety gate passes, auto drafting runs. Follow-ups are sent automatically only when reply tracking (the inbound webhook secret) is configured, so nobody who already replied is followed up. Turning it on needs confirm=true (also through POST /settings) and records the consent (user, time, policy version) in its own option and the audit log; turning it off stops automatic sending at once and returns messages Autopilot approved but did not send yet to draft. Off: exactly the previous behaviour of the individual settings. Approvals made by Autopilot are recorded as "system:autopilot".
* Fixed: with outreach autosend on but "Require individual approval" also on, the Outreach page claimed emails were sent without review while nothing was ever approved. The banner now says that nothing is approved automatically, and the send stage records "awaiting_approval".
* New: sender readiness checks that the sender email's domain can receive mail (an MX record; an A record alone, as on a parked domain, does not count; the Reply-To domain is checked too; cached 12 hours, failed lookups retried after 20 minutes; filter ppclg_mail_domain_dns). If it cannot, automatic sending pauses with the reason and the site email is offered when its domain has MX. A missing SPF record is a warning. CASL: a postal address without a postal code or city is flagged, and an empty outreach postal address defaults to the business address under Settings → Site.
* New: outreach.timezone (IANA). Empty means the WordPress time zone, except that a site left on UTC for a Canadian business uses the zone of its province (ON/QC/NU Toronto, MB Winnipeg, SK Regina, AB/NT Edmonton, BC/YT Vancouver, NS/PE/NB Halifax, NL St. John's). The effective zone and the next send window are shown on the Outreach page and in Settings.
* Grow now: the panel and step labels follow Autopilot; under Autopilot "next actions" list only drafts that need editing instead of every draft.
* New: internal links on Autopilot. Setting seo.auto_apply_links (always on under Autopilot) and seo.auto_apply_per_day (default 20, 1–100). The internal_links job (daily while it is on, weekly otherwise) applies the pending suggestions with the highest relevance first (specific anchors, several and early mentions, products ahead of pages), never more than seo.max_links_per_post per item, through the same safeguards as a click (opaque blocks, DOM check, kses must leave the content unchanged, a revision of the previous content first), audit-logged as "system:autopilot" ("system" when only the setting is on). A suggestion the safeguards refuse is left for a person and not retried. POST /seo/links/undo-auto {confirm: true} removes every automatic link still present: an item not edited since gets exactly its previous content back, an edited one loses only the inserted link; undone links are not added again. The On-site SEO page shows "Applied automatically: N" with "Undo automatic links". Off, links are applied only by hand, as before.
* Fix: internal links on sites with plain permalinks ("/?product=slug"). Every such address (and the home page) was treated as the same link target, so after one link in a post the other suggestions in it were closed as "already links to this target" and a post that linked to the home page got no product suggestions at all. Link targets are now told apart by their query too.
* New: discovery without a search key. While Autopilot is on and Settings → Discovery lists no competitors, the engine asks SE Ranking for your competitors at most once every 30 days (one provider lookup, within the provider_lookups limit), leaves out marketplaces, social networks, encyclopedias, news, government, your own domain and any domain that reads as health, medical or pharmacy, and keeps the result in discovery.competitor_domains_auto, shown and removable in Settings → Discovery (a removed domain is never added back). Competitor backlink mining uses your list plus this one, and the discover step says what it found. With no search key and no usable provider, "Needs you" names the one key that unlocks discovery.
* Grow now / Overview: the Autopilot switch now sits in the "Grow your site" panel. Its confirmation lists what runs automatically (emails per day and week, internal links per day, open-form submissions per day, discover / evaluate / monitor) and the limits that stay on. Once on, the panel says "Autopilot is on — nothing needs your approval", the step labels no longer say "for your approval" or "applied only by you", and "Needs you" lists only genuine blockers: a sender that cannot receive mail, no discovery source, provider credits used up, and owner tasks for sites that need an account (with the Link Growth Submitter hint). Search Console, metrics, SEO-issue and link-review reminders are not listed under Autopilot.
* Autopilot safeguards: a sender that is not ready (a parked domain without MX, an incomplete identity) or the contact cool-down no longer marks drafts as "needs editing"; they wait ("Waiting to approve: …") and fixing the sender approves them at once. Switching Autopilot off also returns what a background run already in progress approved afterwards, before anything is sent, and background settings writes never put an older switch back. Without Autopilot, automation never approves drafts in your own campaigns (as in 1.1.0). Under Autopilot your campaigns email without review only sites at or above min_score_auto_queue; follow-ups without reply tracking and drafts to lower-scoring sites wait visibly and are listed in "Needs you", and waiting follow-ups go out once reply tracking is set up. Listing packages that waited for review are re-checked and queued once they pass. Switching seo.auto_apply_links on outside Autopilot needs confirm=true. Competitor backlink mining counts against the provider lookup limit. Refused automatic links stay refused when the list is regenerated, undone links are never pruned, and the daily summary counts closed suggestions apart. The next send window is right in half-hour time zones, failed DNS lookups are retried after 20 minutes instead of on every request, and the Overview and admin notice name the real sender problem.

* New: storefront compliance check (daily, on growth runs and when products, product terms or menus change). While it blocks and the gate is on, automated submissions become owner tasks and outreach sending pauses; the owner may acknowledge the exact findings.

* New: "Link Growth Submitter" role for handing owner tasks to a staff member or assistant. It can mark a task submitted (listing URL and note; recorded in the audit log with the user id) and nothing else; every other page and REST route refuses it. Settings has a card with a link to add such a user. Uninstalling removes the role and the plugin capabilities. Tasks that need the owner's decision are not shown to this role: a rejected, suppressed or on-hold site, text that fails the claims check, a listing that may already have been sent or would be a duplicate, and outreach pitches. Its listing URL must be on the task's site. The role is created on the first page load after an update, even when the plugin was not reactivated.
* Mark submitted: the listing URL must be an http(s) address; anything else is refused instead of being stored. A listing URL on the site's own domain is refused, and listing verification ignores one, because a page on the own site always links to it.
* Settings: new seo, compliance and growth sections. The storefront acknowledgement and the IndexNow key cannot be changed through the settings form; turning the storefront gate off asks for confirmation.
